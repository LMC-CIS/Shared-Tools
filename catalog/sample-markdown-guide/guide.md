# Writing a Good Tool Description

> **TODO:** Sample guide. Replace or remove once real guides exist.

A clear description helps colleagues decide quickly whether a tool fits their needs.

## Include

- **What problem it solves**, in one sentence.
- **Who it is for** and **where it runs** (for example, Canvas in Chrome).
- **How to use it**, as short numbered steps.
- **What data it touches.** Say plainly whether anything is stored or sent anywhere.
- **Known limits**, such as "breaks if the vendor changes the page layout."

## Avoid

- Real student names, IDs, or grades in examples or screenshots.
- Passwords, API keys, or access tokens.
- Internal web addresses that only work on campus.

## Example

> *Grade Column Highlighter* adds color to late submissions on the Canvas gradebook page. It runs only in your browser and sends nothing anywhere.
