Contribute

Built something useful for teaching, advising, or running a course? Share it. You can add it yourself on GitHub, or send it to a maintainer who will add it for you.

Maintainers: the contact email and submission form below are still placeholders. Update them in site.config.json.

Before you share: checklist

Every submission needs all of these. Maintainers check them before merging.

  • FERPA and student privacy have been considered.
  • No credentials, passwords, API keys, or access tokens are included.
  • No real student data appears in examples or screenshots (use made-up names like “Student A”).
  • Data handling is described in one plain sentence.
  • The author is credited.
  • It has been tested in the environment it says it runs on.

Option 1: Add it on GitHub (no command line needed)

You need a free GitHub account. Everything happens in your web browser.

  1. Open the catalog folder and choose Add file → Create new file. (If you don’t have write access, GitHub will offer to make a copy, called a fork, for you. Accept it.)
  2. In the name box, type your-tool-name/tool.json. Typing the / creates the folder. Use lowercase letters and hyphens.
  3. Paste the contents of the tool.json template and fill in each field. The field meanings are in the README.
  4. Optional: add a README.md in the same folder with a longer description, written in Markdown.
  5. If the tool’s files live in this repository, upload them to the same folder (Add file → Upload files) and list their names under "files". If the code lives in its own repository, put that link in "source" instead.
  6. Choose Commit changes → Create a new branch → Propose changes, then Create pull request. The pull request shows the checklist; tick each item.
  7. An automatic check reads your tool.json and explains anything that needs fixing in plain language. A maintainer then reviews and merges it.

Option 2: Send it to a maintainer

Not on GitHub? Send your tool to a maintainer and they will add it for you.

Please include:

  • The tool’s name and a one- or two-sentence summary.
  • What type it is (bookmarklet, AI skill, guide, workflow, app, extension, or other).
  • Who it is for (students, faculty, staff) and what it runs on (for example Canvas in Chrome).
  • The files, or a link to where the code lives.
  • One sentence on what data it reads, stores, or sends.
  • How you want to be credited, and a contact address.
  • Confirmation that you have gone through the checklist above.

Do not email passwords, tokens, or any real student data.

Changing or retiring your tool

Edit the tool’s tool.json on GitHub (the pencil icon) and change "status" to "unmaintained" or "retired", or ask a maintainer to do it.
